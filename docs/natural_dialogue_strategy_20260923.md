# “读稿感 / AI 味”系统优化策略（2026-09-23）

**优先级更正：用户明确将读稿感、口音/韵律及情绪自然度排到最后。本文保留作后续方案，暂不启动新实验
或索要评分；先处理原始TTS的明显badcase，漏词/乱读/重复等内容失败不在此延后范围内。**

## 新反馈与当前证据

用户新增反馈：“读出来的音频有些片段像读稿子，或者AI味太重”，要求系统化优化。
本次尚未指定新增片段的语种、时间点或具体 take；登记为总体反馈，不把之前的沙哑、
自动低韵律标签或任意候选自动升级成已确认的读稿坏例。用户仍只负责声学异常比较，
不能要求其判断五语种口音、措辞自然度、表演地道性。

这一目标应独立于“ASR 内容完整”和“没有爆音”：两项都通过的声音仍可能缺少对话节奏。
混音改动可以提高可听清程度，但不能由此声称合成韵律改善。

已核 DIS `f30291c` 源码中现有能力：

| 环节 | 实际已有 | 本次要验证的缺口 |
|---|---|---|
| 译文 | `domain/language.py` 的五语种口语 profile；`translation/backends/openai_chat.py` 已有本地口语/语义审核和缩译保护 | 实际最终文本是否落成书面长句、称谓错误或按中文句法断句；已有 prompt 不等于实际通过 |
| 话轮 | 识别提示保留同人话轮/真实停顿；`performance_beats` 已随合并话轮交给翻译 | 不合理碎句是否反复重起句，真实反应/转折是否被合并抹掉；锁定旧脚本重渲不会重新识别 |
| 表演 | `_compose_voxcpm_style_instruction` 有短反应克制、手动锁定、置信门和同角色风格一致性 | `isNarration`/`scene_context` 误标会走“steady natural pacing”的旁白默认；须核真实 cue，尚未证明发生于这次投诉 |
| 参考 | 参考/身份链保护、续写、reference-only 救援 | 中英文 ref 是否干净同人、prompt 音文是否真匹配；相同身份不等于适合当前语气，不能随意换成本国语另一个人 |
| 时间/后处理 | `process_segment` 有短句裸音保护、停顿压缩、`time_stretch_filters` 和超窗缩译 | 对同 take 比较原输出、实际变速/停顿处理后、混音后；rubberband 保共振峰不等于保自然韵律 |
| 电平 | 默认 `MIX_VOICE_LEVEL_MODE=source`，uniform 也有基于可信表演证据的电平偏移 | 实际运行模式、限幅和 EQ 是否削弱强弱变化；不能把“响度更齐”直接计为“更像真人” |

## 按顺序实施

### 1. 先定位“在哪一层变得像读稿”

对能恢复同一 take 的片段，保留相邻一轮对话上下文，做三段对比：
服务端返回 WAV → 最终 segment → 混音/编码。对比段级处理时匹配试听响度；
测试背景遮盖时保持同一人声电平，不分别归一化混音。身份、实际 ref、文字、参数和 SHA 一起冻结。

- 裸输出自然，变速后平/急/拖：优先处理文本长度与安全时间窗，而不是重新采样模型。
- 裸输出尚可，成片不清：使用当前局部背景 A/B 定位遮盖；不把提高音量当表演增强。
- 裸输出本身平、停顿机械：才进入文本/控制/参考/模型的单变量诊断。
- 旁白式稳定节奏：核 narration/内心独白标记、有效 control 及来源；真实旁白也不能全改成激动对白。

暂缺裸输出时，只保留混音层的主观反馈及候选定位，不用混音切片冒充该 take 的生成层证据。

### 2. 对话文本与时间预算一起处理

复用现有翻译审核，先核听起来生硬的片段及上下句：说话对象、关系、语体、语义重音、目标语短语边界。
修订保持人物关系、指代、否定、数字、条件与句尾意义；标点只表达自然语义结构。
不为“口语化”机械加 lah/ba/啊、不随机加停顿、不用感叹号造情绪、不把所有台词缩成短口号。

若文本确实过长，先尝试同义口语压缩、合法邻近留白或有依据的同人分句；
不得越过换人/原有停顿/镜头语义边界，不靠硬裁正文或加速一切来满足字幕窗。
若文本很短且窗很长，保留合理沉默，不拉长字音、追加废词或强行填满。

只对候选启用额外重写/试听；正常台词复用已有整集识别、翻译审核与缓存，不全片增加调用。

### 3. 控制强度与身份稳定性分开试

先对照一条简短、来源可靠的中/英文表演指令与原有效控制；不要同时换 ref、seed、CFG、步数或文本。
检验时两边固定同一 conditioning 模式：若带控制走 reference-only，则无控制侧也固定 reference-only，
避免把 combined/reference-only 的变化混在“情绪开关”里。请求 seed 与回传有效 seed 都记录。

候选指令只表达一种已知说话意图/语气，比较克制控制是否足够；不自动对所有台词追加
“非常激动/夸张/富有表现力”，也不全局去掉情绪。短反应、耳语、喊话各自保留原保护。
如检查同一角色上下句续写，保持角色 ID 和真实参考一致；风险 take 不能续写或进入干净缓存。

既有 E01 情绪开关 A/B 两边都被用户确认异常，偏好 B 不等于通过；不重新索要同一听评，
也不能据此推断所有读稿感都由情绪控制造成。

### 4. 输入可靠后做模型与数据实验

已有 24 条 base/r8 计划属于沙哑归因，仍为 0 生成，不能当成读稿自然度验收。
新定位的读稿 case 另登记，先每个变量 ≥3 个相邻 seed；冻结后不能改写旧计划或覆盖旧 WAV。
基座/r8/较低 LoRA 强度分阶段做，不同时扫描 CFG、步数、情绪与参考。

- r8 相对基座更平：先评 LoRA 强度或基座回退，不能直接续 r8 更多 epoch。
- 两者都平且已排除文本/参考/后处理：建立明确数据假设，再做 r8 warm-start 或基座初始化的单变量对照。
- 首个数据假设优先为“干净、自然的真人短对白及不同长度完整话轮覆盖”，或“可信同人 ref 覆盖”，
  二选一；有可靠表演标注才补控制前缀，不从 F0/能量自动造情绪标签。

自然对白可以来自已获授权的访谈/对话/录音，不要求一定是短剧，也不能凭这些来源名认定真人和授权。
现有朗读数据留作发音及五语种回放，不等于有足够表演示范；实际读稿原因仍须实验验证。
继续使用各目标语种 17 + 中文 10 + 英文 5 的既有起点，投影关闭，不同时更改配比/步数/投影。
远端复用已验训练池，来源、身份/session/原音频/PCM/文本隔离通过后才允许入训练清单。
合成正常候选仅供开发诊断，不冒充真人自然对白或独立验证集。

## 验收与最小下一轮

先定位少量真实读稿片段和对应正常对照，分别做处理层、文本或控制中的一个变量，
不展开全参数网格。新生成的局部听评包同时保留实际 ref/prompt、模型身份能取得的证据及原始 QC。

工程轨记录：实际 tempo、被删除的停顿/硬裁、控制及来源、首 take 声学风险、同身份跨 cue 波动、
固定总预算后残留率、实际调用数和耗时。上述指标仅辅助定位，没有“F0 越起伏越自然”的自动门。
内容维持 Whisper large-v3 离线口径，逐语种检查退化；正常片段不加常规双 ASR 或生成预算。

用户继续只标明显声学异常与自己能判断的相对听感，可留空；口语、重音、语调、当地自然度和
表演适切性由对应母语评审单独判断，MS 必须是马来西亚母语者。未评维度保持未验证。
不得用 CER、ASR 语言标签、LLM 自评或总体平均分替代五语种验收。

当前完成的是源码链路核查与此方案；尚无新增读稿坏例的 take 定位、生成 A/B 或自然度改善结论。
局部背景试听和编码峰值补丁可独立推进，不因独立 GPU 尚不可用而停下所有工程工作。
