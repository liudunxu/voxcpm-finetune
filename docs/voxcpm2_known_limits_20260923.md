# VoxCPM2 已知限制、规避与微调边界

联网核查日期：2026-09-23。范围为官方模型卡、使用/微调指南、技术报告和上游公开 issue/回复。
本次上游 `main` 与本项目只读 submodule 均为 `f772e498a45fbb5fb8e13fbf9b9c48be9fe33e69`；
这只核实源码版本，不证明生产服务代码、权重或 GPU 预处理结果相同。

证据分级：**A**＝官方文档/论文/源码或上游贡献者明确回复；**B**＝公开用户报告，未完成独立复现；
**C**＝本项目建议验证的假设。Issue 仍 open 不证明所有环境均有问题，closed 也不等于模型已修复。
未下载 issue 附件音频或训练数据，未重新生成、听评、评分、部署或训练；以下不是新的质量验收。

## 结论

VoxCPM2 的主要短板是困难输入下的稳定性、细粒度可控性及跨语言属性解耦，不能概括成“音质差”。
官方已支持 TH/TL/VI/ID/MS；支持列表、48kHz 输出和低 ASR 错误率均不等于当地口音/对白自然度达标。
微调适合有明确数据缺口的语言、风格、说话人适配，可能降低部分坏例概率；不是所有异常的通用修复。
“读稿感”不是一个已被证明的单一模型缺陷，必须区分台词、参考、控制、模型、变速和混音。

## 质量问题与处置矩阵

| 跨语言时带入源语言口音/节奏 | A：贡献者在 #321 明确确认 Hi-Fi/Ultimate 会同时复制音色、韵律、发音习惯与口音。[S5] | 目标语口音优先时对照 reference-only；同身份、同真实参考，不凭同名换人，不把模式变化混入控制 A/B | 目标语及可信同人 ref 数据可能改善；普通 LoRA 不保证完全解耦音色与源口音 |

| 长句后半段加速、蜂鸣、失真、音色漂移 | A：指南及 #372 贡献者2026-08-11回复承认尚未彻底解决。[S3][S7] | 按语义/句界分段、保持同一身份参考；仅对风险句对照较低CFG，拼接处另验节奏/音色；不要把300字等个例当统一阈值 | C：匹配长话轮的数据可能改善，尚无本次查到的受控证据保证普通LoRA根治；不为它绕过当前30s备料约束 |

| 说完后额外乱读、停不下来 | B：#352为VI/nano-vllm报告，无回复；“EOS失败”是报告者推测。A：微调FAQ列出长尾静音等风险。[S10][S4] | 先检查实际引擎/输入，区分静音和额外人声；做内容+尾部QC。长度比重试不是内容正确保证，不能凭VAD裁未知正文 | 数据边界/转写问题应先修数据；可靠证据下可研究停止损失，但必须同时防漏尾，不能用一次权重调整宣称解决 |

| 数字/货币/日期读法不适配目标语言 | A：当前TextNormalizer仅按“含中文→zh，否则→en”分支，并非30语种归一化器。[S13] | 使用目标语规则与文本审核；本项目已有这层，不重复建。不要对TH/TL/VI/ID/MS一律打开上游normalize=True | 真正发音缺口可训练；错误数字展开属于上游文本错误，不能靠微调让它稳定纠正 |
| 微调后不听指令、忽略文本、克隆变差 | A：#305明确说明无控制样本微调会损伤指令跟随；官方FAQ提示小集几百步就可能过拟合。[S4][S14] | 先核实际LoRA加载/强度，保留早期checkpoint与基座对照，不只看loss | 修训练分布、加入可信控制/同人ref及回放，才是对应修法；更多epoch可能加重问题 |

## 哪些值得优先微调

1. **已有语言中的稳定发音/韵律缺口**：目标语准确转写、音素/词形覆盖、自然口语数据。
   五语种是已支持语言的适配，不是从零新增语言；官方“新语言500+小时全量训练”不能直接套用到本项目。
2. **自然对白与表演风格**：有场景、完整话轮及可信表演标签的真人录音，区别于再加一批平读朗读。
   这是与“读稿感”最匹配的数据假设之一，不是已经验证的病因或收益。
3. **参考条件下的说话人稳定性**：同一真实说话人、不同录音的ref→target配对，覆盖实际跨语种使用方式。
   官方建议30–50%样本含同人ref；不能靠角色名或相邻时间窗自动认定同人。
4. **重复可复现的特定音色/短句失败簇**：先证明不是输入/处理链错误，再收相匹配的真实正例。
   目标是降低固定回归集失败率，不是把发生失败的合成WAV当训练目标。

以上是可实验方向，不是承诺。LoRA先于全量：官方推荐语言/风格r64、enable_dit=true、
LoRA lr约1e-4；全量约1e-5。保留training_cfg_rate=0.1、weight_decay=0.01和中英文回放。[S4][S15]
官方1–3epoch经验主要针对单说话人，不能直接当作联合模型最优步数。
本项目既有r64/alpha64/dropout0.05、投影关闭等配置不因这份调研自动改变；也不直接续训r8。

## 标准微调不直接解决的事

- **错误参考身份、分离污染、误裁尾、过度变速、混音与编码失真**：先修真实调用链。
  公开反例 #343 起初被报为模型漏尾，报告者最后确认原始TTS正常、问题在自己的端上链路。[S16]
- **VAE编码/解码能力缺口**：当前官方训练脚本在构建TTS优化器前移除audio_vae，LoRA和常规全量TTS微调
  都不等于训练VAE。[S17] 若干净真人样本重建已失真，需要单独的VAE研究/模型版本选择；
  重建正常只能降低对VAE的怀疑，不能单凭这一项认定LLM病因。16k输入/48k输出也是该结构的既定边界。
- **并发、推理引擎、seed透传或缓存错误**：属于工程问题。例如 #390 的LoRA WebUI未把seed传给generate，
  当前源码仍可见此调用缺口；不能当作“固定seed模型仍随机”的证据，更不能推定本项目调用也有此bug。[S18]
- **实时接口与成本**：官方generate_streaming提供音频分块，不是文本逐token输入的双向流式。[S3]
  FAQ所列VoxCPM2约0.3 RTF是在4090、10步及compile启用下的数字，不代表本项目20步及完整QC耗时；
  应靠分句/服务调度和经验证的推理引擎处理，不靠微调解决。[S19]
- **精确时长、完全解耦、任意长文无漂移**：普通LoRA没有这类保证；更深的建模/训练改动仍属研究假设。

## 对当前r8项目的最小行动建议

1. 按用户最新优先级，先降低原始TTS明显badcase，处理已有严重反馈；读稿感、口音/韵律、
   情绪自然度与混音润色全部排最后，暂不启动相关新实验。漏词/乱读/重复等内容失败仍优先处理。
   保留r8至诊断有结论，缺raw的case先补证据；已有E01两侧仍异常、M01/M02持平，
   不支持“全局去情绪”或“默认压背景即可解决”，不等待用户新增读稿时间点。
2. 沿用已冻结24条沙哑base/r8诊断，仍为0生成，不修改原计划或seed组；新增读稿case另建回归。
   原始客户端ref对照不等于GPU预处理后的完整生产重放。
3. 对反复破音的可靠参考，可增加独立VAE重建诊断；当前未执行、未得到VAE归因结论。
4. 新对照每次只动一个变量：先实际控制/模式，再LoRA强度或基座；新实验使用≥3相邻seed。
   控制开关两侧固定reference-only，冻结ref/prompt字节、文本、有效CFG/步数/seed及模型文件身份。
   使用实际生产输入口径；常规CFG基线1.8，指南的1.5–1.6仅作风险样本候选，不全局降CFG或增步数。
5. 只有稳定失败与数据假设匹配时才开定向训练；先补数据质量/身份/控制覆盖，不重复r10/r11无收益组合。
   保持普通4次/强风险共享6次总预算；官方“生成1–3次”不是在每一层另加次数的授权。
6. 五语种分别验收内容、声学坏例与语言质量。用户只做能判断的声学反馈；自然度/口音/表演由对应母语者评，
   MS需马来西亚母语者，缺评记未验证。自动ASR或F0变化不能替代听评，也不因此阻塞离线候选实验。

## 检索时特别排除的误读

- #357评论中的“加引号/破折号”建议与其报告内的重复率排序互有矛盾，未当作跨语种通用修复。[S6]
- #385中的“合成参考watermark导致尖刺”只是用户猜测，未当作已证根因。[S8]
- 不将社区建议的[breath]等标签当作已验稳定接口，不给所有台词机械加语气词、喘息或随机停顿。
- 官方多语言ASR榜单包括不同测试集/识别后端；不能与本项目Whisper large-v3冻结分数混算，
  也不能据其均分证明五语种当地口音或对白自然度。
- 运行FAQ对标准vLLM的旧兼容性描述不能覆盖当前README的vLLM-Omni专用支持；
  不把普通推理框架、专用适配器与本项目OmniVoice服务混为一谈。
