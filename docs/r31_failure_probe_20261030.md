## 结果与取舍

**淘汰整体LoRA强度减半方向，不据此自动降低训练学习率。** 同四文本的配对结果：

| 条件 | ID CER（20条） | TH CER（20条） | 近全静音 | 疑似多读 |
|---|---:|---:|---:|---:|
| base | 14.42% | 9.74% | 0 | 0 |
| r30 | 14.80% | 6.32% | 0 | 0 |
| r31强度1 | 13.62% | 17.19% | 1 | 1 |
| r31强度0.5 | 17.20% | 18.55% | 0 | 2 |

TH1983/control/s45从静音变成有声，但CER仍51.31%；TH1994/control/s43仍疑似多读、CER69.23%。
没有证据证明整体减弱适配器能稳定消除故障。

**正文括号是部分大错的触发因素，但不能全局机械替换。** 以下均为同条件5seed均值：

| case | base原标点→逗号 | r31原标点→逗号 |
|---|---:|---:|
| ID1816 plain | 43.75%→0.89% | 44.108%→0.89% |
| ID1707 plain | 7.84%→13.922% | 7.056%→14.706% |
| TH1983 control | 10.576%→3.978% | 28.272%→8.166% |

ID1816在base和r31上都明显改善，不能将这类遗漏全部归因为微调；half强度仍为43.75%。
TH1983改逗号的10条r31输出没有空ASR或近全静音，但不能据此证明后续不会再出现。
ID1707是句尾缩写SANParks，机械转换会产生`, SANParks,.`形式，且ASR有缩写/外来词写法差异；
本结果仅否定此次机械变换在这条句子上的收益，不能据此认证实际发音错误或全盘否定文本预处理。
代码核对未发现直接删除正文括号内容的解析步骤，不把模型对输入形式的反应说成已经定位到parser bug。
